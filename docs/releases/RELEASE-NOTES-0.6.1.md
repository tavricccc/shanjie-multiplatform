# 善解 Windows 0.6.1

日期：2026-10-14。修正升級時新舊 DLL 共存造成的設定通知循環，以及提權安裝工具的無限等待。沿用 0.6.0 功能、schema 6、上游 pin、內建詞庫及 model-v5／classes-v3。

## 升級期間的設定讀取

0.5.3 讀取設定會寫回 schema 5，0.6.0 會寫回 schema 6；仍開啟的舊版程式與新程式可能互相改寫同一份 `profile.ini`。每次保存又通知其他程式重新讀取，形成循環。0.6.1 的 TSF 與設定介面只在記憶體中遷移；讀取不改檔、不建立備份、不廣播。使用者明確儲存時，才備份舊格式及原子保存。

儲存及重啟使用 v2 通知，非同步排入訊息佇列；0.5.x／0.6.0 不接收這些通知，避免舊 DLL 再次改寫。新版本仍接受舊設定窗的 v1 通知，但只讀取。原生通知視窗類別也使用獨立的 v2 名稱，避免同一個程序內的新舊 DLL 誤用彼此的回呼。

較新的未知 schema 不被降版或覆寫。舊版視窗保留原本設定，更新後須重新開啟應用程式或登出再登入，才能完整使用新版本。

## 提權程序等待

安裝／解除安裝管理程式以 `MsgWaitForMultipleObjectsEx` 等待，期間處理視窗訊息。程序退出優先於持續到來的訊息；每批處理至多 64 個訊息，等待上限為 10 分鐘。逾時或收到結束訊息時，提示管理員工具可能仍在執行，不宣稱安裝成功，也不強制終止或自動重跑安裝。正常退出保留原來的退出碼；控制代碼及等待錯誤均會檢查。

## 驗證界線

本版使用隔離 profile、真實舊 DLL、測試專用隱藏視窗及無提權子程序驗證。沒有在目前系統安裝、更新註冊、控制使用者核心或修改私人設定。背景測試不能替代真實 UAC／系統升級與 Windows Terminal 驗收；結果與證據見 [VERIFICATION.md](https://github.com/tavricccc/shanjie-multiplatform/blob/68796049b3f19a67217c15c559ea8be2819ad3e2/VERIFICATION.md)。
