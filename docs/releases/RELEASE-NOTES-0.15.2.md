# 善解輸入法 0.15.2

以 0.15.1 為基礎的測試修正版（pre-release）。本版仍有下列已知混打問題；更新前請保留目前可正常使用版本的安裝檔。

## 已知問題與暫時處理方式

標準注音下，啟用上游判斷後，數字／注音判斷與 Windows 前端的空白處理、混打流程尚有銜接問題。本版未修復以下情況：

| 中英混打方式 | 哎呦：`9 空白 u . 空白` | 設定：`gk42u/4` |
| --- | --- | --- |
| 兩者並用（僅標準注音） | 可能變成空白＋`9優` | 可能變成 `社/4` |
| 上游判斷（僅標準注音） | 可能變成空白＋`9優` | 此按鍵序列正常 |
| 注音順序自動判斷（Windows 版） | 此按鍵序列正常 | 此按鍵序列正常 |
| 關閉 | 此按鍵序列正常 | 此按鍵序列正常 |

這是程式問題，不是使用者按錯、模型缺詞或私人詞典格式有誤。0.15.2 修正資料換行、恢復數字表載入後，暴露了這些尚未整合完整的流程；已以正式 DLL、設定及模型副本在隔離 TSF 環境重現。

**暫時處理方式**：開啟善解設定 →「中英混打與切換」→「中英混打方式」，改選 **「注音順序自動判斷（Windows 版）」**，再按主視窗的 **「儲存」**。此方式可避開上述兩項問題，仍保留 Windows 混打判斷；暫時停用上游混打及其數字／注音自動判斷，不需刪除個人詞典或模型。這是設定上的暫時繞過方式，並非程式已修復。

## 修正

- **個人詞典重複詞條導致核心無回應**：個人詞典與內建詞層、姓名或詞包出現相同讀音及字詞時，以個人詞典的分數為準，不再讓整個引擎載入失敗。完整個人詞典保留，不需刪掉重複項目；同一字詞的其他讀音、上游手動詞條保護及詞包資訊也保留。
- **「正在完成上一段組字」後無法繼續輸入**：收尾要求遭拒或寫入失敗後可重試；文字已寫入但結束組字失敗時，只重試結束。較早排隊的工作在新要求接手、原組字終止或輸入法停用後失效，避免改寫新組字。
- **收尾卡住時的 Esc**：即使目前組字區已空，仍可接收 Esc。收尾中的 Esc 會保留應用程式畫面上的原文字、取消待處理按鍵，並嘗試結束舊組字；若應用程式仍拒絕編輯，會顯示可重試的提示。
- **Windows 換行造成資料表失效**：出貨詞庫與詞包由固定 Git commit 匯出，保留原本的 LF 換行，避免 checkout 自動轉成 CRLF 後數字表無法載入。測試資料採同樣做法。

## 個人資料與安裝

執行 `Shanjie-Windows-Setup.exe` 更新。沿用既有設定、個人詞典、學習及下載的模型；私人字典不包含在本安裝檔中。從舊版更新後，請重新開啟會使用輸入法的應用程式；登入預載則在重新登入或重新開機後確認。

本版沿用上游 v0.6.1 與原本的內建模型組。回歸測試使用隔離的核心與 TSF 輸入環境；真實 Codex、AyuGram、Store 等應用程式的日常使用、更新與登入行為仍需安裝後驗收。

若再發生收尾問題，錯誤階段與 HRESULT 會以限量、節流方式記在該宿主的 `%TEMP%\shanjie-tsf.log`，不記錄文字、詞條或按鍵內容。請保留錯誤發生時間與宿主名稱；暫存位置可能因應用程式封裝而不同，重新開機也可能清除暫存。
