# 善解 Windows 0.5.0

日期：2026-10-12。上游仍固定 `368eebc426981852094d8c0c49b8b0618143bd2b`，模型仍為 model-v5／classes-v3。

## 本版三項更新

1. **登入後常駐核心**：安裝程式登錄 `ShanjieCore` 登入啟動項目，啟動沒有視窗的 x64 `tools/shanjie-core.exe`。標準及倚天的 x64／x86 前端透過本機管道共用核心程序中的詞庫、模型映射與候選索引；每條連線使用獨立組字狀態。閒置時仍保留核心，至登出或明確停止。
2. **Ctrl + 單引號輸入頓號**：開啟 Ctrl 標點快捷鍵時，`Ctrl + '` 插入 `、`。組字中的既有中文與頓號保持可編輯，不提前提交；`Ctrl + Shift + '` 仍為 `＂`。
3. **中英混打尊重 Caps Lock**：中文模式、中英混打開啟且「Caps Lock 切英文」關閉時，英文依 Windows 的 Caps Lock／Shift 狀態輸出大小寫。注音判讀使用原始按鍵，英文原文另行保存；大小寫切換不影響中文組字。

## 啟動與恢復

Windows 登入啟動可能延後；前端在核心尚未啟動時可自行啟動同一核心，並等待初始化完成再處理該次按鍵。核心連線中斷後，重建專屬會話並重播尚未提交的組字；重播期間停用學習，避免重複記錄。按鍵及重播日誌只保存在記憶體中。

管道限定本機、使用者及登入工作階段，設有使用者 SID 權限，前端連線後核對伺服器的執行檔路徑。不同安裝版本與隔離設定使用不同端點。核心解析後的不可變詞庫與模型使用有界快取；更換個人詞庫或資料版本會建立相應資源。

更新後請重新開啟已開啟的應用程式，並登出再登入，讓新版登入啟動設定生效。解除安裝會移除登入啟動項目，並停止本登入工作階段的已知核心。舊檔改為移到原目錄旁的 `.deleted_files`，使用中而無法移動的檔案先保留，沒有永久刪除或自動重新啟動。

## 驗證界線

本版的兩架構原生輸入回歸共 64 項通過：Caps Lock／Shift 四種組合、切英文設定開關、輸入途中切換 Caps Lock、中文後接英文、空白及組字中的頓號、Caps Lock 下的中文注音，核心未就緒時立即連續輸入，以及文字欄位切換；涵蓋標準及倚天鍵盤。

常駐核心整合驗證包含獨立會話、另一個程序同時輸入、核心停止後恢復未提交注音，以及四個同時啟動的會話；詞庫與模型載入計數皆為 1。第一次自動啟動核心至會話就緒的最後單次樣本為 570 ms；閒置核心約 39.8 MiB Private／95.2 MiB Working Set。這是隔離測試樣本，並非各種 App 的鍵盤到畫面延遲保證。

設定 UI、DLL、管理程式與核心均為 0.5.0 套件。未更動系統目前安裝的輸入法、使用者設定或個人學習資料；尚未進行實際登入、前景應用程式或解除安裝的系統驗收。詳細結果見 `../../VERIFICATION.md` 與 `../PERFORMANCE.md`。
